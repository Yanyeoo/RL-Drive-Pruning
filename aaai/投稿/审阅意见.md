# Part 1 [The Review Report]

**Summary：**本文提出 DriveToken，一个面向自动驾驶 VLA 的两阶段视觉 token 剪枝框架：先以 LambdaRank 蒸馏模型内部注意力来学习 token 排序，再通过基于 NAVSIM 驾驶质量奖励的策略优化，为每个场景动态分配保留比例；论文报告其在 AutoVLA-3B 上以平均保留 35.5% token 获得 0.9107 PDMS 和约 43.3% 理论 FLOPs 降幅。

**Strengths：**

1. **研究问题重要，贡献定位具有实际意义。** 相较于只在固定比例下选择 token，本文同时研究“保留哪些 token”和“每个场景保留多少 token”，并尝试直接以轨迹质量和安全子指标作为优化目标。这一问题比通用 VLM 中基于注意力、相似度或重建误差的剪枝更贴近自动驾驶部署需求。

2. **固定预算下的 token 排序结果具有一定说服力。** 在 NAVSIM、50% 保留率和相同物理 token 移除协议下，DriveToken SFT 达到 0.9045 PDMS，高于 SparseVLM 的 0.8774、FastV 的 0.8191以及注意力教师的 0.8901。LambdaRank 相比 MSE 的 0.9045 对 0.8894，也说明直接优化排序比回归注意力幅值更适合 Top-K 选择。

3. **框架较轻量且完成了真实 token 移除。** 约 0.59M 参数的 scorer 不修改冻结的 VLA 主干，论文也区分了训练期 attention masking 和部署期 physical removal，避免将纯掩码实验直接包装为实际计算节省。该工程设计具有潜在复用价值。

**Weaknesses (Critical)：**

1. **主结果存在明显的协议不公平，当前证据不足以支持“Budget RL 优于所有基线”的核心结论。** 表1明确说明基线报告 raw scores，而 DriveToken Budget RL 使用 confidence-based runtime fallback；表2甚至写明除特别说明外均使用该 fallback。由于 fallback 会把约1%至2%的高不确定场景恢复为完整720-token推理，它同时改变了准确率、安全性和平均计算量。论文没有报告 Budget RL 在关闭 fallback 时的 PDMS，也没有给所有基线应用相同的回退规则。因此，0.9107 与无剪枝的0.8988、固定预算 SFT 的0.9045以及其他方法之间并非严格同协议比较。尤其是 NC 从0.987提升到0.994，很可能部分来自 fallback，而不一定来自动态预算策略本身。

2. **缺少 matched-compute 的动态预算对照，无法归因于“按场景分配预算”。** Budget RL 平均保留35.5% token，但论文只提供25%、50%和75%三个固定剪枝点，没有在35.5%平均保留率下比较固定比例 DriveToken、随机预算、按置信度启发式分配、动态版现有方法，或同等平均 FLOPs 的其他策略。仅凭“59.5%的场景保留不足40% token”只能证明预算输出有分布，不能证明预算与场景难度或安全风险形成了有意义的条件依赖。0.9107相对固定50% SFT 的提升还同时混入了保留率变化、scorer 的 RL 更新和 fallback，因而不能归因于 budget adaptation。

3. **Stage 2 对 token scorer 的策略梯度缺乏严格成立的目标。** 论文主动承认式(6)的 selection surrogate “不是子集上的有效概率分布”，但随后将其作为 `log π` 的一部分代入策略梯度目标。这样得到的梯度不是所定义联合动作策略的标准无偏策略梯度，也没有给出该替代目标与期望驾驶奖励之间的理论关系。更严重的是，论文没有做“仅训练 budget head”“冻结 scorer”“仅用 surrogate 更新 scorer”“可微 Top-K或其他梯度估计器”等关键消融，无法确认0.9107究竟来自有效的联合策略学习，还是来自未经控制的启发式排序更新。这是方法严谨性上的结构性问题，而非单纯表述不清。

4. **统计证据不足，关键提升可能处于训练波动范围内。** 论文只为 Budget RL 的单个 checkpoint 报告场景 bootstrap 置信区间 `[0.9071, 0.9143]`，但没有报告独立训练随机种子、均值与标准差，也未对 Budget RL 与 SFT 或 No Prune 做配对差值检验。场景 bootstrap 只能估计固定模型在测试场景上的采样不确定性，不能覆盖 RL 训练、动作采样和 checkpoint 选择造成的方差。当前核心增益仅为相对 SFT 的0.0062和相对 No Prune 的0.0119，至少需要3至5个独立训练种子及配对置信区间才能支撑稳定提升的主张。

5. **跨模型与跨数据集泛化主张明显超过实验支持。** 论文将3B到7B的迁移描述为“confirming backbone-agnostic generalization”，但7B实验只报告相对于注意力教师排序的 pairwise accuracy 0.856，没有在 ImpromptuVLA-7B 上报告剪枝后的规划质量、保留率、FLOPs或延迟。nuScenes实验因 KV-cache 不稳定，仅得到48个非空预测，作者也承认完整量化评估留待未来。因而现有结果最多说明 scorer 能拟合另一个模型的注意力排序，不能证明驾驶性能层面的跨模型或跨数据集泛化。

6. **“部署效率”结论主要依赖理论 FLOPs，实际收益尚不充分。** 在H20上，50%保留率仅将单场景延迟从2.16秒降至2.08秒，即3.6%；论文没有报告核心动态配置35.5%保留率下的端到端延迟、P50/P95/P99延迟、显存峰值和吞吐量，也没有实测其声称更有收益的7B配置。43.3% FLOPs 降幅与实际延迟收益之间存在较大落差，当前结果更适合表述为计算量削减，而不足以支撑显著推理加速或可部署性。

**Rating：4/10（Reject）。** 选题重要、固定预算 scorer 结果有价值，但核心动态预算结论受到不公平 fallback 协议、缺少 matched-compute 对照、非严格策略梯度构造及统计和泛化证据不足的共同影响，尚未达到 AAAI 主会所要求的实验归因与方法严谨性。

# Part 2 [Strategic Advice]

**问题根源：**

第一项和第二项问题的根源是**实验设计未隔离变量**。当前 Budget RL 同时改变了预算、token 排序器、平均保留率和 fallback 协议，却把最终提升整体归因于 reward-driven dynamic budgeting。审稿人无法判断收益来自场景自适应、RL 微调、额外保留的困难样本，还是完整推理回退。这里不是简单补一句说明可以解决，而是主表的比较协议需要重新设计。

第三项问题属于**方法定义与实际优化算法之间的不一致**。既然 selection surrogate 不是有效的子集策略概率，就不应直接把它写成联合策略的 `log π` 并沿用标准 policy-gradient 解释。可以将其明确改写为 advantage-weighted ranking auxiliary loss，与合法的 Gaussian budget policy loss 分开；或者采用具有明确梯度估计依据的随机子集采样、Plackett-Luce、Gumbel-Top-K、REINFORCE 或其他可微排序方法。若不修改方法表述与实验验证，这会持续成为理论审稿人的主要攻击点。

第四项问题来自**将测试集场景不确定性误当作完整实验不确定性**。NAVSIM场景数量很大并不能消除RL训练随机性。单次训练的场景 bootstrap CI 很窄，但它不能证明换一个随机种子后仍能获得0.006左右的增益。

第五项和第六项问题主要是**主张过度而证据边界没有被守住**。pairwise accuracy 测量的是对教师排序的拟合，不是规划效用；理论 FLOPs 也不是端到端加速。方法本身未必因此无效，但当前摘要、贡献列表和结论使用了“confirming”“backbone-agnostic generalization”“deployable”等偏强措辞，扩大了审稿攻击面。

**可救性判断：**

协议公平性、matched-compute、统计稳定性和效率报告在有完整训练与评测代码的前提下可以通过补实验解决，属于**可救但工作量较大的实验缺陷**。这是当前版本能否从拒稿区间进入边缘接收区间的关键。

Stage 2 scorer 更新目标是更深层的问题。如果现有实现确实把非概率 surrogate 当作 policy log-probability使用，则属于**方法层面的结构性缺陷**。仅增加文字解释不足以消除问题，至少需要重新定义优化目标、给出合理推导，并用消融证明 scorer 更新确实有效。如果重新训练后效果消失，则论文的“joint selection-budget RL”贡献需要降级为“动态预算学习加辅助排序微调”。

跨数据集结果当前基本不可用，但它并不是主方法成立的必要条件。若短期内无法修复 nuScenes 管线，应删除或显著弱化该部分，而不是保留48个有效预测并声称跨数据集验证。跨7B规划性能则更重要，因为论文将跨模型泛化列为独立贡献；若无法完成，应从摘要和贡献列表中移除。

闭环验证是重要限制，但对以 NAVSIM 为主要基准的 AAAI 论文而言，不一定单独构成致命问题。真正致命的是论文以 safety-aware 为核心叙事，却没有证明动态策略在困难场景中比同计算预算方法更安全。可通过风险分层分析部分缓解，不必立即完成真实车辆测试。

**行动指南：**

1. 重建主表，统一所有方法的 fallback 设置。至少同时报告 `Budget RL without fallback`、`Budget RL with fallback`、`SFT without fallback` 和 `SFT with the same fallback`。对每一行同时计入 fallback 后的真实平均 token 数、FLOPs和延迟，不要只报告名义预算。

2. 在平均35.5%保留率下增加严格 matched-compute 对照：固定 `r=0.355` 的 DriveToken scorer、随机场景预算但同平均保留率、基于 scorer entropy 的启发式预算、仅训练 budget head 且冻结 scorer，以及可获得的 input-adaptive baseline。最关键的比较是“相同 scorer、相同平均 token 数、唯一差别为动态预算策略”。

3. 做完整的因子消融，将 Stage 2 拆成 `SFT scorer + fixed budget`、`frozen scorer + learned budget`、`joint training without selection surrogate`、`joint training with surrogate`、`reward without delta`、`reward without safety penalty`、`reward without efficiency bonus`。同时扫描 `λ_e`，绘制 PDMS或安全指标与实际 FLOPs的 Pareto 曲线，避免只展示一个人工选择的权重点。

4. 重新表述或重构式(6)至式(7)。若保留当前实现，建议将总目标明确写为合法的 budget policy-gradient loss 加一个 advantage-weighted ranking auxiliary loss，不再称其为联合动作的策略概率。还需说明 advantage 是否对 ranking loss stop-gradient、归一化方式以及该项的尺度控制，并与至少一种有理论依据的 Top-K 梯度估计方法比较。

5. 使用至少3个、理想情况下5个独立随机种子重复 Stage 2。报告 PDMS、NC、EP、平均保留率和 fallback rate 的均值与标准差，并对同一场景上的 `Budget RL − SFT`、`Budget RL − No Prune` 做配对 bootstrap。模型选择必须只依赖验证集，最终 navtest 只运行一次固定配置。

6. 证明预算确实是“场景自适应”的，而不仅是数值变化。按交叉路口、弱势交通参与者、遮挡、交通密度、速度和基线 PDMS 对场景分组，报告各组的平均保留率及安全指标；分析预算与基线场景难度、scorer entropy、NC/TTC风险之间的相关性，并展示高预算和低预算代表案例。若困难场景没有获得更多 token，应停止使用“safety-critical scenarios demand more tokens”这一核心叙事。

7. 补充动态35.5%配置的真实系统测量：batch size 1下的P50/P95/P99端到端延迟、吞吐量、峰值显存、KV-cache占用、scorer与budget head开销，以及 fallback 后的加权平均延迟。若7B只能完成部分实验，至少提供同一硬件和同一实现下的完整延迟测量；否则将“更大模型会带来更大绝对收益”改为待验证假设。

8. 只有在 ImpromptuVLA-7B 上报告完整规划指标后，才保留“cross-model generalization”贡献。需要比较无剪枝、固定预算和动态预算下的规划质量及效率。当前0.856 pairwise accuracy 应改称“attention-ranking transfer”，不能作为任务级迁移证据。nuScenes若仍无法完成稳定评估，应从主实验和贡献中删除，并作为 limitation 简短说明。

9. 在 Rebuttal 中不要把回应重点放在“NAVSIM有11,576个场景”或“bootstrap CI很窄”。更有效的回应是提供关闭 fallback 后的结果、matched-compute 对照和多种子统计。如果来不及补齐，应主动收缩主张：把论文定位为“PDMS-guided token ranking and preliminary dynamic budgeting”，而不是已经验证完成的安全、自适应、跨模型部署框架。
