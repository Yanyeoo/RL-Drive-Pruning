## 1. 根因诊断（从代码 + 日志实锤，非推测）

### 根因 1：token_net 的 PG 梯度是"非法 surrogate"，且在持续破坏 SFT ranking

**证据**（v5 训练日志 `logs/v5_train/train_sh0.log`）：
```
[step 569] logp(b/s) = -0.436 / -41.526
[step 602] logp(b/s) = -0.716 / -63.646
```
`selection_log_prob` 从健康值 −10 一路漂移到 **−41 ~ −63**。而 softmax 的
log-prob 物理下界是 `−log(720) ≈ −6.6`。出现 −40 以下的数，说明 token_net 的
score 尺度在训练中**爆炸性漂移**（softmax 极端饱和）。

**代码根因**（`train_scorer_budget_rl.py:340-343`）：
```python
selection_log_prob = (
    token_scores[top_indices].sum() - B * torch.logsumexp(token_scores, dim=0)
) / B
```
这个 surrogate 的梯度会**持续推高被选中 token 的 score、压低整体 logsumexp**，
导致 score 尺度单调发散。KL penalty 用的是 `F.mse_loss(p_curr, p_ref)`（不是真
KL divergence），对 score 尺度的约束太弱，压不住这个漂移。AAAI 审稿人 #3 已经
点名这是"非法 PG"。

→ **这是 v3-v5 退化的直接原因**：scorer 的 ranking 被 REINFORCE 梯度破坏。

### 根因 2：per-token counterfactual 的信号物理上太小

**证据**（v6 训练日志 `logs/v6_train/train_sh0.log`）：
```
[step 25] grad=0.002
[step 38] grad=0.003
[step 47] grad=0.003
...（绝大部分步 grad_norm ≈ 0.002-0.003）
[step 50] grad=16.421（唯一异常，loss=3.5764）
```
swap 单个 token（720 个里换 1 个）对轨迹/PDMS 的影响 < 0.001，所以
`A_i = R_pruned - R_{-i} ≈ 0`，梯度几乎为 0。**这不是 bug，是 r=0.5 剪 360 个
token 时单 token 边际贡献天然趋近 0 的物理事实。**

→ v6 per-token counterfactual 方向在当前配置下**无有效学习信号**。

### 根因 3：budget policy 的 REINFORCE 方差爆炸 + 随机游走

- scene-level reward，每 scene 只采一次 Gaussian action
- advantage 用 8-16 scene 的 group mean 估计，方差极大
- **结果**（v5 日志末尾）：kr 从 0.55 无脑漂到 0.42，即使 v5 已经去掉
  efficiency_bonus，kr 仍在下降 → policy 学不到"何时该剪多少"

### 根因 4：reward 没做 delta（相对 no-prune），被 scene 难度淹没

代码里已经算了 `baseline_trajectory`（no-prune 轨迹），但**只用于 safety_loss**，
reward 用的是绝对 PDMS product。绝对 PDMS 被 scene 难度主导（easy 0.98 vs
hard 0.4），pruning 的净效应（往往 ±0.001）被淹没在难度噪声里。

## 2. 改进方向（按优先级，可落地）

### 方向 A（最高优先级）：换掉非法 surrogate → 可微 Top-K + 直通梯度

把 token 选择变成**可微**的，让 token_net 的梯度来自真实 PDMS 差分，而非非法
surrogate。两个实现选项：
1. **Gumbel-Softmax 软 mask**：采样松弛 keep-mask，PDMS 通过 mask 对 token_net
   反传（PDMS 对 mask 不可微处用 straight-through / finite-difference 近似）。
2. **Straight-Through Top-K**：forward 用 hard top-k，backward 按 rank 把梯度
   近似传回 score。

→ 这是方法层面的真正新颖点，也是 ICLR 的核心贡献（对应审稿人 #3 的修复）。

### 方向 B：加 Critic（value baseline）+ PPO 降方差

训一个 value net 估计 V(scene feature)，`advantage = R - V`，PPO clip。
直接解决 budget policy 的随机游走（根因 3）。

### 方向 C：Delta reward（pruned vs no-prune，同 scene，改一行）

`reward = pruned_PDMS - no_prune_PDMS`（或 ratio）。代码已算 baseline_trajectory，
只需把 reward 从绝对 PDMS 改成相对 delta。消除 scene 难度（根因 4），突出
pruning 净效应。

### 方向 D：DPO / 偏好学习替代 RL（最省 GPU，值得先试）

用 SFT scorer 做 reference，构造 paired preference 数据（同 scene 两种 keep 集，
PDMS 高低作偏好），直接优化 scorer 的 ranking。避开 REINFORCE 高方差，且天然
对齐 ranking 目标。这是"确定性 preference"路线（§11 已证 PDMS 是确定性的）。

### 方向 E：hard-example mining / curriculum

§12.4 已发现：1.3% catastrophic scenes 贡献全部 −1.275pt；hard scenes（r1<0.8）
上 scorer +18.7pt。RL 应 focus 在 scorer 失败的 scene，或加大 hard scene 采样权重。

## 3. 推荐组合拳 + 时间线

**短期（1 个 GPU 窗口内可验证，成本最低）**：
1. 先上 **C（delta reward，改 1 行）+ B（critic baseline）** → 看 budget policy
   是否停止退化、kr 是否稳定。
2. 同时开发 **A（Gumbel-Softmax / straight-through 替换非法 surrogate）** →
   这是 ICLR 的方法贡献核心，必须做。

**中期**：A+B+C 若仍不超 SFT，上 **D（DPO）**，DPO 最稳、最省 GPU。

**判断标准**（复用 v5 的验收线）：
- RL PDMS > 0.892（超 SFT）→ 方法成立，继续逼近 no-prune
- RL PDMS 逼近/超越 0.899（no-prune）→ SOTA 达成
